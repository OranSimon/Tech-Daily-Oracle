## 3. Top Developments

### 1. Bloomberg: Nvidia GB300 NVL72 现身上海 Alice Huang 关联数据中心
- **核心事实**：Bloomberg 调查称，两家中国公司在上海"长三角项目"数据中心安装了 Nvidia GB300 NVL72 机架（Nvidia 最强产品之一），序列号出现在 2026 年 11 月提交给中国监管机构的文件中；上海 Shuoyao 将该硬件作为抵押获得 9600 万元人民币融资。这与美国对 Blackwell 级别的出口限制直接冲突。
- **我的判断**：这是今天唯一"改变事实基础"的消息。它同时证明三件事：①中国对顶级美国算力的需求在管制下依然强劲；②第三国转运或灰色渠道确实存在且已形成可抵押的资产化市场；③Nvidia 及其服务器伙伴的最终用户核查存在结构性缺口。对 Nvidia 的直接财务影响可能有限（规模未披露），但**监管后果是中期变量**：BIS 调查、分销商/OEM 审计、许可证审查趋严的概率上升。
- **不确定性**：单一信源（Bloomberg），序列号真实性未经独立验证；Alice Huang 的具体角色不明；无法量化走私规模，因此不能据此推翻"Nvidia 中国收入中期下滑"的判断。
- **Signals to monitor**：BIS 是否将 Shanghai Shuoyao 或长三角项目运营实体列入实体清单；Nvidia 下季度 10-Q 是否新增最终用户核查风险的表述。

### 2. Nvidia 治理：黄仁勋复职、$290M 和解、市场只读到了前半句
- **核心事实**：董事会在接受辞呈约两周后"重新任命"黄仁勋为总裁、CEO 兼董事；消息公布后科技股走高（Bloomberg 市场快照）。同日 Nvidia 就以 2018 年加密挖矿 GPU 销售误导投资者的八年集体诉讼达成 2.9 亿美元和解，不承认不当行为。FT 另指出公司行为准则更新后，黄仁勋的署名信已从伦理表述中移除。
- **我的判断**：三条新闻的组合比任何单条都重要。**复职解决的是"谁签字"，没有解决"程序为什么需要复职"；和解清掉了一项法律悬置，却把历史披露信誉问题重新拉回视野；行为准则删信是一个低烈度但高含义的信号——治理的可解释性在下降，而不是上升。** 市场给的是战略连续性溢价，不是治理折价。
- **不确定性**：董事会程序文件未公开；复职是否有政治介入（此前报道称白宫介入）尚无公司层面确认；和解不含认错，法律上不构成对历史披露的否定。
- **Signals to monitor**：12 月国会听证是否落到文件层面；S&P 是否最终下调评级；是否有董事辞职或以不连任方式表态。

- **核心事实**：OpenAI 反诉 Apple，指控其窃取商业秘密、"胁迫和威胁"同时与两家合作的供应商、并以不公平雇佣协议阻止人才流动。此前 Apple 已就商业秘密提起诉讼。

### 4. 出口管制的双面性：中方"落后九个月"与封锁漏洞同时成立
- **核心事实**：Tom's Hardware 报道，由于亚洲 GPU 租赁漏洞被封堵、chip stack 成熟化与 distillation 打击，中国 AI 模型可能落后竞争对手至多九个月；事件将受影响方列为 DeepSeek、Alibaba、ByteDance、Tencent、Huawei。同一周 Bloomberg 报道顶层 Blackwell 硬件已在上海落地。
- **我的判断**：**这两条不是矛盾，而是管制真实形态的两个侧面——它成功压低了"规模化前沿训练"的可获得性，但没能阻断"小批量顶级硬件"的流入。** 对中国实验室而言，真正的约束不是买不到芯片，而是买不到足够多、足够稳定、足够可规划的芯片；对 Nvidia 而言，真正的风险不是卖不出，而是卖出去了但说不清怎么到的。前者利好 Huawei Ascend 的中期替代逻辑，后者构成合规与法律风险。
- **不确定性**："九个月"这一数字无法用可复现的基准验证，属媒体/分析估计；封锁漏洞的具体规模未披露。
- **Signals to monitor**：IDC/TrendForce 关于 Huawei Ascend 份额的季报；Nvidia 中国区收入是否跌破单季 $4B。

### firecrawl/firecrawl — 给 AI agent 的统一 web 数据接入层

- **Language:** TypeScript
- **What it does:** 用统一 API 完成 search、scrape、crawl，并把网页转成 LLM-ready Markdown，供 agent 与应用消费。

- **Risk:** 强信号，但竞争激烈；837 个 open issues 与 AGPL-3.0 是两个真实的商业化约束——前者是维护债，后者会限制托管服务形态。

## 6. Papers & Research Frontiers

### OS-Omni: Benchmarking Generalist Computer-Using Agents on Long-Horizon Workflows Across Platforms
- **Authors / Lab:** Hui Shen 等（大型多机构合作，含 Ping Luo、Wenhu Chen 等）
- **Source:** arXiv 2611.34232 / HuggingFace Daily
- **核心贡献:** 提出跨 Windows/Ubuntu 等平台的 live benchmark 与执行环境，评测通用 computer-using agent 在长时程、跨应用、状态持久化任务上的表现。
- **技术意义:** 现有评测把 web、mobile、desktop 割裂开，而真实工作的特点是"跨系统 + 状态不丢"。这是把 agent 评测从"单步正确"推向"长时程可靠"的关键一步，对产品选型有直接约束力。
- **Code/Demo:** 未见公开
- **信号强度:** medium（概念价值高，但摘要截断、任务规模/基线结果/代码均未披露，"live"环境的可复现性存疑）

### AIChipBench: Benchmarking LLM Agents for Automated AI Accelerator Design
- **Authors / Lab:** Guangyuan Wang 等（机构未标注）
- **Source:** arXiv 2611.33093 / HuggingFace Daily
- **核心贡献:** 让 LLM coding agent 用可综合 RTL 实现量化 Transformer decoder，并用可执行的整数参考模型约束跨 token 状态更新的正确性——不只测"输出对不对"，还测"硬件状态对不对"。
- **技术意义:** 把 AI 辅助芯片设计从 demo 推向可评测。若基准与代码公开，它会是"LLM 能不能真的写硬件"这一问题的第一个严肃标尺，对 EDA 与加速器设计流程有长期含义。
- **Code/Demo:** 未确认
- **信号强度:** medium（叙事热、但机构未知、arXiv ID 形似未来编号需核实、范围仅限 decoder RTL）

### Evaluation-Free Recursive Self-Improvement for Coding Agents
- **Authors / Lab:** Zhe Ren、Guowei Rong、Jürgen Schmidhuber 等（机构未标注）
- **Source:** arXiv 2611.21056 / HuggingFace Daily
- **核心贡献:** 提出把 downstream task evaluation 从 coding agent 的候选筛选回路中移除，以降低评估成本并避免对固定评测过拟合。
- **技术意义:** 直击 evaluate-and-select 范式的两个真实痛点（评估成本随探索线性上升、对固定评测过拟合）。Schmidhuber 的参与会带来关注度，但"evaluation-free"这个措辞可能比实际方法更宽。
- **Code/Demo:** 未见
- **信号强度:** medium（无量化结果，摘要截断，实际增益未验证）

### Solve Vision with Code: Coding Agents Are Stronger Visual Reasoners Than Video Models
- **Authors / Lab:** Dezhi Luo 等（机构未标注）
- **Source:** arXiv 2611.34813 / HuggingFace Daily
- **核心贡献:** 受控比较后主张：在视觉任务执行类基准上，能生成并执行代码的 coding agent 比视频生成模型更可靠地完成视觉推理。
- **技术意义:** 这直接挑战"视频模型即视觉推理器"的近期评估范式。如果结论稳健，会同时影响 benchmark 设计与产品技术选型（是该上视频模型，还是该上 agent + 代码执行）。
- **Code/Demo:** 未见
- **信号强度:** medium（结论强、证据弱：摘要截断、无量化结果、任务覆盖未知，结论很可能高度依赖任务类型）
